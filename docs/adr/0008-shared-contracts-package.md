# Cross-module events live in a shared `contracts` package from M3

From M3-3, dispatch and order listen to each other: dispatch consumes `OrderReady` (M3-2), and order consumes `CourierAssigned` (M3-3), with `CourierUnassigned`, `OrderPickedUp` and `OrderDelivered` to follow in M3-4 and M3-5. While each event lived in its publisher's module, that made the cycle order → dispatch → order, which Spring Modulith's `ModularityTest` rejects. So the events move to a top-level package, `io.github.danie1le.dropoff.contracts`, now instead of at M5-2: `OrderPlaced`, `OrderCancelled`, `OrderReady`, the `Actor` enum they carry, and the new `CourierAssigned`. Modules depend on `contracts` and never on each other for events. The package holds records and enums only, with no Spring and no dependency on another module (`ContractsPackageTest` checks both), and changes to it are additive. This is the same rule `contracts` has after the split (decision #31), so M5-2 only moves the package into its own Gradle module and changes no imports.

`common` was rejected as the home: it holds Spring-dependent web and validation helpers bound for `libs/web-common`, a different destination with different rules. Keeping each event in its publisher's module and breaking the cycle with a Modulith named interface or an `allowedDependencies` exception was also rejected: it keeps the two modules tied together and leaves M5-2 to move every event anyway.
