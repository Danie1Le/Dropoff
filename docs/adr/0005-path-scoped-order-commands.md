# Path-scoped command endpoints for order status

There is no auth, so a single `PATCH /orders/{id}/status` cannot tell whether the merchant, the courier or the customer is calling. Instead, each step is a `POST` command scoped to the caller, with the caller's id in the path: `/merchants/{id}/orders/{orderId}/accept` is one. Merchants also have start-preparing, ready and cancel; the assigned courier has pick-up and deliver; customers have cancel. The API table in `docs/roadmap.html` holds the full list. Courier commands live in the order module, because it owns order status. A caller the order doesn't belong to gets 404, and a command that doesn't fit the current status gets 409. Repeating the command that produced the current status is a 200 no-op: no new `order_events` row is written and no event is published. `order_events.actor` records who caused each step. `GET /orders/{id}` stays unscoped for live tracking. An `actor` field in the request body was rejected: anyone can fill it, and one generic endpoint would carry every rule. When auth arrives, the path id is checked against the logged-in user and no URL changes.
