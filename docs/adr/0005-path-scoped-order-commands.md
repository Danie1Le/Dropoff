# Path-scoped command endpoints for order status

There is no auth, so a single `PATCH /orders/{id}/status` cannot tell whether the merchant, the courier or the customer is calling. Each step is a `POST` command with the caller's id in the path instead: `/merchants/{merchantId}/orders/{orderId}/accept`, `.../start-preparing`, `.../ready`, `.../cancel`; `/couriers/{courierId}/orders/{orderId}/pick-up`, `.../deliver`; `/customers/{customerId}/orders/{orderId}/cancel`. A caller the order doesn't belong to gets 404, a wrong state gets 409, and repeating the command that produced the current status is a 200 no-op. An `actor` field in the request body was rejected: it puts identity in a field anyone can fill, and it keeps one generic endpoint that has to document every rule at once. With path scoping, each command validates and documents one step. When auth arrives, the path id is checked against the logged-in user and no URL changes.
