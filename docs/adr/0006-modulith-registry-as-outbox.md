# Spring Modulith's event publication registry is the outbox

Events must reach Kafka if and only if the change that caused them commits, so the project needs a transactional outbox. Module listeners already use `@ApplicationModuleListener` from M2, and that writes every event to Spring Modulith's `event_publication` table in the same transaction and retries incomplete ones. At M5, `spring-modulith-events-kafka` relays events annotated `@Externalized` to Kafka from that same table, and completed publications are deleted. A hand-written `outbox` table with a `SKIP LOCKED` relay job was rejected: it duplicates what the registry already does and adds code to get wrong. `order_events` stays a separate, permanent audit history; the outbox only holds events until they are delivered. `CourierLocationUpdated` bypasses the outbox and goes straight to Kafka, because losing one costs nothing.
