Dropoff

A real-time order and courier dispatch backend for a three-sided delivery marketplace: customers place orders, merchants prepare them, couriers deliver them. Java 21, Spring Boot 4, PostgreSQL, Redis, Kafka. Everything runs locally in Docker Compose for $0.

      Architecture

      Start as one Spring Boot app with a package per domain (ADR-0001). At M5, when Kafka arrives, split it into three services. Enforced module boundaries keep that split mechanical.

      merchant module order module dispatch module

      * One database or one schema per service, where the WebSocket endpoint lives, and how order-service gets menu prices are open in Service split: data ownership and cross-service price lookup. Cross-module foreign keys get dropped at the split (ADR-0003).

      Only from PLACED or ACCEPTED (before the merchant starts preparing). Any other jump is rejected with 409 Conflict. Rules live in Java; a CHECK guards the column. Who counts as "merchant" or "courier" with no auth is open in Who may change an order's status without auth?

        Data model

        Flyway SQL migrations create every table; Hibernate only validates (ADR-0002). Ids are BIGINT identity, money is integer cents with CHECK (>= 0), times are TIMESTAMPTZ. Hover a table to light up the tables it links to.

        merchant order dispatch infrastructure (M5) PK primary key FK foreign key UQ unique

        API

        REST endpoints documented with springdoc (Swagger UI). Every REST path sits under /api/v1; errors are RFC 9457 Problem Details with a code field, settled in API conventions: errors, versioning, pagination. Endpoints for customers, merchant open/close and item availability are open in Missing endpoints. Who may call the status endpoint is open in Who may change an order's status without auth?; accept/decline endpoints for couriers are open in Courier offer lifecycle.
