Dropoff

A real-time order and courier dispatch backend for a three-sided delivery marketplace: customers place orders, merchants prepare them, couriers deliver them. Java 21, Spring Boot 4, PostgreSQL, Redis, Kafka. Everything runs locally in Docker Compose for $0.

      Architecture

      Start as one Spring Boot app with a package per domain (ADR-0001). At M5, when Kafka arrives, split it into three services. Enforced module boundaries keep that split mechanical.

      merchant module order module dispatch module

      * One Postgres container with one database per service (merchant_db, order_db, dispatch_db). order-service owns the WebSocket and prices orders from local merchant and menu-item copies fed by two compacted topics. Cross-module foreign keys are dropped at the split (ADR-0003, ADR-0007, Service split: data ownership and cross-service price lookup).

      Order flow

      How one order moves through the system, start to finish. This is where the modules, stores and events tie together.

      PLACEDcustomer
      →
      ACCEPTEDmerchant
      →
      PREPARINGmerchant
      →
      READYmerchant · starts dispatch
      →
      PICKED_UPcourier · needs a courier
      →
      DELIVEREDcourier
      CANCELLED
      Only from PLACED or ACCEPTED (before the merchant starts preparing). Any other jump is rejected with 409 Conflict. Rules live in Java; a CHECK guards the column. The merchant or the customer can cancel, and the system cancels a PLACED order nobody accepts within 10 min. Each step is its own command endpoint, scoped to the caller (ADR-0005, Who may change an order's status without auth?).

        Data model

        Flyway SQL migrations create every table; Hibernate only validates (ADR-0002). Ids are BIGINT identity, money is integer cents with CHECK (>= 0), times are TIMESTAMPTZ. Hover a table to light up the tables it links to.

        merchant order dispatch infrastructure (M5) PK primary key FK foreign key UQ unique

        API

        REST endpoints documented with springdoc (Swagger UI). Every REST path sits under /api/v1; errors are RFC 9457 Problem Details with a code field, settled in API conventions: errors, versioning, pagination. Customer, open/close and availability endpoints are settled in Missing endpoints. Order status moves through path-scoped command endpoints, one per step, settled in Who may change an order's status without auth?; couriers poll for their open offer and accept or decline it, settled in Courier offer lifecycle.
